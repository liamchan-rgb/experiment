# Build74：节点建筑与数量联动

用户要求每类节点有相应建筑；输入总数时自动补齐分配，各数值同时支持滑块。总数仍4—30，起点固定1：改总数按40%战斗/30%奖励/1Boss分配，其余为空地。改单类保留当前值，优先调整空地，再按战斗/奖励/Boss顺序补差；改空地不足时补入战斗。超出总数的类别值限定到总数−1，额外环路随地图规模收紧。无效/未完成输入禁用生成，已生成结果在编辑后立即失效。

每个节点恰有一件绑定nodeID的建筑，起点复用蓝营帐，四类采用新增透明资源。建筑显示矩形互不重叠，避让道路、人物驻足点和标记。先排最受约束建筑，有限回溯，不静默丢建筑。地块随行数增长，生成版本2记录coordinateHeight；原生道路Mask、SpriteKit地面/雾、Metal接收网格/道路UV/阴影范围、相机边界和缩略图使用相同高度。大型地图沿用缩放/拖动浏览。版本1离线数据原样保留，不承诺不同生成器版本下同种子布局不变。

点击建筑关联实际道路节点，仍仅林地预览，不结算怪物/奖励，不写营地存档。本轮没有新增正式探索引擎、节点编辑器或人物动作。后两项仍为M3正式探索/战斗/奖励接入与地图存档，M4单节点内容编辑。

验证：181项Swift包测试；648组4—30规模/种子地图；额外24组4/10/30、四种单一类别、0/最大环路极端配额；78组正式适配/道路/巡逻检查。正常行走动图和整图来自生产Swift采样、实际资源的离线合成，光影近似，不是设备截图，不测实机FPS。设备Release编译与IPA校验见Media/Build74；实机运行交用户。
