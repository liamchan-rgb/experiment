- 援护：施法者到友方的绿金引导，目标恢复/成盾；振奋：节点友方短促金光与增伤buff
- 三药水复用已核图标/回血/护盾，补使用动作、目标选择、库存数量及实际结果绑定
- 复活石：玩家保留倒地形体，晶体聚光→起身→半血恢复；同节点2AP救援，下轮行动，不做怪物同款消散

### B2 突袭、普通攻击与八件基础装备

### B4 龙骑士三技能

### B5 两套套装与两个套装技能

## 资源分层与工作量边界

- 6件可见武器、4件护甲：UI图标与人物资源分开。人物可见行走部件遵循现有八方向×13姿势合同（104绑定，不等于104张都手工重画），战斗另验待机/起手/施放/受击/收势持握与遮挡。行走背负，战斗按武器类型持握；不改人体/步相来迁就衣物。完整自由混搭仍按既有合同缺口分项，不能凭两件预设算完成。
- 4件饰品和4消耗品优先做UI图标、属性/状态、使用效果，不默认给药水/戒指画八向人物模组。装备不应永久强发光遮挡人物。
- 技能光效优先做参数化发射方向、目标挂点、时间曲线和独立层，不按八个行走方向各重画一套完整火焰/爆光。19个ID的技能/怪物意图图标可按族共享底形，但映射与含义清晰。
- 复活需要玩家倒地形体和起身动作；怪物HP0随伤害数字右吹消散。二者不能共用立即删除身体的死亡处理。大型怪物盾面/照明/地面锚点随各自体型，不能直接套主角240原生圆盾或把当前鹿灵当六种正式怪。

## 表现与规则接入要求

1. 表现仅读完整提交回执与公开快照，以会话/结果ID去重；不在动画里重新掷骰、扣AP、改变buff轮数、重复掉落。多目标一次伤害骰、各目标实际扣盾/HP、施法者自疗和奖励是同一结果的不同表现通道；末敌死亡仍播放附带自疗/盾等结果。
2. 以当前八方旅人式观感制作：施放压暗、受击局部高亮、粒子照明与地面碰撞，低/高阶的形状/运动/节奏有区别。没有蓄力等级；强技能悬停给固定强度预示，不因停留变强；提示圈在正式出招时消失。不增加参考视频运镜。
3. buff显示小方框，hover/focus/触屏详情给来源、幅度和真实剩余轮数；盾/生命继续用条，AP按build51/52用黄色菱形。增伤不盲目叠加，以GameCore覆盖/持续规则为准。伤害D20自然20只读原骰标志，不能以伤害总和≥20猜测。
4. 护盾给值按max；满血时不凭空冒恢复数字；药水普通治疗不救倒地者。复活石同节点救援，消耗2AP/1石，回半最大生命向上取整、下轮才行动；本轮可见状态/队列同步。
5. 补多角色/多目标后测最重并发预算，更新目标60Hz、动作按时间推进、图集采样/解析发射连续；缓存/复用光池，避免每个技能常驻一套大图集。旧8帧650ms合同是历史资源事实，不直接锁死新特效帧数。

## 每批交付标准

- 主线程亲自修复和审核，查看全场构图、整身1×/2×、全帧接缝/手握/衣口/腿/背剑/新武器与圆盾覆盖；新资源不因旧版本通过而自动认可。
- 实际提供正常速度GIF、可复制HTTPS直链和站姿/关键帧；关键连续变化补连续采样。GIF不能证明设备60fps，必要时另给正常60fps视频但不冒充实机。
- 先独立样片复核，再接受控demo，单体/群体/自疗/格挡/致死/无效目标/倒地救援分别核对；真实规则接入是明确工作，不仅播放预设剧本。
- 所有原稿/判退稿/清单/来源/时间/挂点保存；原资源不覆盖，记录增量和待确认；artApproval默认null。
- 仅做美术审核/适当纯逻辑验证/设备编译，不运行模拟器或实机；用户负责安装和实机反馈。当前任务只做计划，不开制作、不打包。
