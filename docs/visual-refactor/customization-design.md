# P1 五官与性别自定义 · 设计稿 v1（待用户确认）

用户决定（2026-11-06）：同一身体、性别体现在头部；五官逐项可选；美术＋渲染＋界面由视觉分支负责；排在技能特效之前。

## 现状（已核对当前分支）

- 绘制顺序：`weapon.back → hair.back → 衣服下层 → 身体/衣服/装备 → head.base → face.eyes/brows/nose/mouth → hair.front → 双手`。
- 五官和前发都是“头部局部”图：每个方向每个部位只有 **1 张**（脸 4 部位 × 8 方向，前发 8 张），按每帧的 `headToCanvas` 矩阵贴到头上。
  所以新增一种眼睛＝画 8 张小图（背向三个方向为空），不是逐帧重画。
- `head.base`（头部皮肤轮廓）属于身体包，随帧变化。
- 实测 208 个行走格（两套外观 × 8 方向 × 13 姿势）：**手从不压到头部**；背后武器从不碰到后发。
- 60 张 P1 地图图集全部由同一个分层合成器 `scripts/compose-character-parts.py` 离线烘焙，发型和脸目前绑死在衣装预设上（林间绿衣＝栗发蓝眼，行旅蓝衣＝银发琥珀眼）。
- 战斗场景：P1 的发型和脸是两张独立侧视图 `MeadowBattleHeroHair` / `MeadowBattleHeroFace`；持弓时头部取自弓图集的 head 分组，需单独处理。
- 存档里只有 `appearanceID`（衣装预设），结构在 Codex 的 `ClassroomGameCore` 包里。

## 方案

### 1. 离线：把“头”从图集里拆出来
用同一合成器，对每个装备状态（2 衣装 × 5 武器 × 无甲/皮甲/符文甲＝30 种）烘焙两张不含五官和头发的底图：
`under`（`hair.back` 之前的层，主要是背后武器）和 `body`（其余全部，含 `head.base` 和双手）。
再为每个五官/发型变体离线贴好位置，烘焙成与图集同布局（13 列 × 4 行 × 2 张）的透明“部件页”。全部用现有 Python 合成器，像素与现有流程一致。
**原有 60 张图集名称、尺寸、锚点不动**，默认外观仍用它们；新文件另外加入。

### 2. 运行时：选定外观后在设备上合成一次
按 `under → hair.back → body → 眼 → 眉 → 鼻 → 嘴 → hair.front` 叠成与原图集同格式的两张图，后台线程完成，
再注入人物精灵缓存和 Metal 阴影纹理缓存（以合成名登记）。之后的播放、阴影、方向、锚点、步态时序完全照旧，不增加每帧开销；
同时只占用和现在一样的两张图集显存。肤色用调色板替换（肤色色阶需与衣物颜色不重叠，烘焙时校验）。

### 3. 美术：新增部件
- 每个部位先做 3—4 种（眼睛含带睫毛的女性向款、眉、鼻、嘴），眼睛颜色 4—5 种（离线调色生成）。
- 发型：保留现有 3 种，新增 2—3 种女性向（长发需要 `hair.back`，长发与背后武器的遮挡逐方向检查）。
- 肤色 3—4 档。
- 战斗侧视的发型/脸为每个变体各画一张；持弓头部改为同样叠加。
- 每批按仓库规定交正常速度全身 GIF 与可访问链接，主线程审核，新美术需用户认可。

### 4. 界面与存档
- 营地/新行程中新增“外观”界面：性别（只影响默认推荐和发型列表排序，不锁选项）、发型、眼型、眼色、眉、鼻、嘴、肤色，实时八方向行走预览。
- 外观单独存于 `Application Support/MeadowCamp/p1-appearance-v1.json`，不改 Codex 的存档结构和 formatVersion；
  文件不存在时使用当前衣装预设对应的默认头，老存档完全不受影响。衣装（绿衣/蓝衣）仍沿用原 `appearanceID`。

## 不改
寻路、点击、镜头、战斗规则、存档格式、原图集名称/尺寸/锚点、步态数据、方向绑定。

## 分步交付（每步可单独审核）
1. 离线拆头 + 运行时合成器，只用现有两种头验证：合成结果与原 60 张图集逐像素一致（这是正确性的硬指标）。
2. 第一批五官/发型变体 + 审核 GIF。
3. 外观界面 + 外观文件 + 战斗侧视同步。
4. 女性向发型/眼型扩充与整体审核。

## 代价
- 安装包：新增 60 张底图 + 部件页，估计 +15—25 MB（以实测为准）。
- 设备：换外观时一次性合成约 0.2—0.5 秒（后台），平时零额外开销。
