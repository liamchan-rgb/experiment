# 人物行走资源与验收

`python3 scripts/prepare-living-assets.py` 同时重建环境及人物图集。离线工具依赖 Pillow、NumPy、SciPy；运行时没有第三方依赖。

原始角色美术保存在 `Art/Generated/LivingScene/hero*-gait-v1.2.png` 和 `hero*-diagonal-v1.3.png`。`scripts/prepare-gait-assets.py` 为每个朝向指定独立腿部蒙版，分离大腿、小腿、刚性靴子，按两段关节链生成 24 帧。鞋不会沿小腿长度缩成尖点。衣摆下的连接保持重叠，不能用删除整只断腿来通过连通检查；只有小于 64 源像素的边缘残屑可以清理。

build 28 起，脚踝仍按原关节链移动；鞋靴保持刚性并围绕脚踝向本方向的行进轴收拢 18°，减少原画左右鞋尖分别向外撇的效果。旋转同时应用于导出的分层蓝靴帧。

图集是 25 列（待机 + 24 个行走姿势）、4 行、每格 256 像素。`Directions` 行序为下、左、上、右，`Diagonals` 为右下、左下、左上、右上。右侧面按完整左侧面镜像输出。运行时每个格子独立裁切，透明 UV 不跨格；Metal 投影从相同原图格采样。新增动作格时必须同步 `HeroFrames` 的格数、打包规则和 `hero-gait.json` 足底数据。

`hero-gait.json` 存储每只脚的横向坐标、未抬脚时的地面纵深和抬脚高度。阴影根据地面纵深接地，人物和阴影不使用独立步态计时。

承重半周期中脚以恒定速度后移，抵消人物前进。摆动半周期使用平滑越过和抬膝。源骨骼坐标按俯视相机投影，因此纵深方向的移动速度和动画相位也必须应用 `WalkCycle.projectedScale`，不能独立调快切帧掩盖滑步。

验收要求：iPad 实际地图中检查三位人物八方向的接触、承重、抬脚及两次过腿，正常速度和四分之一速度都要看；暂停后可用单步逐帧检查。还需覆盖启动、地图与步态入口往返、缩放和阴影渲染。连通、帧哈希不同和编译成功只能证明部分技术条件，不能证明动作自然。云端录像保留原时间轴，真实 M1 iPad 上的安装、发热和 GPU 驱动行为仍需与模拟器结论区分。

小腿蒙版必须只包含靴筒，鞋尖不能同时出现在靴筒与脚掌两层。P3 的原待机被长裙覆盖，上腿缺少可用画面，摆腿时使用本组原角色美术中的深色裤料填充覆盖区；不能把白色裙摆像腿一样拉到靴口。衣摆下很短的源蒙版在仿射投影后也只允许以最终像素计的有限关节重叠。各段按地面前后位置排序，而非固定先小腿后脚；二维绘制约束让膝盖位于靴口之上，避免相机投影把小腿贴片翻成倒置的靴子。
