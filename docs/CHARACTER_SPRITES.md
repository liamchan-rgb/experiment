# 人物像素精灵制作标准

本文是人物像素精灵的制作标准。人物全部由代码绘制，不使用外部图片素材，同一套算法有两份实现：

- **网页制作工具** `hd2d-walk-demo/`（TypeScript）：用来设计、预览、导出。
- **游戏内烘焙器** `Sources/Game/Characters/`（Swift）：MeadowJourney 启动时现场合成人物，支持运行时换装。

改形状、换衣服、换发型、改五官，都按本文的约定写数据或代码，两端保持一致（见第 8 节）。

- 工具：`hd2d-walk-demo/`，Vite + TypeScript，依赖只在开发期使用。
- 预览：`npm run dev` 打开首页，地址参数 `?scale=4&s=0.65&weapon=weapon_staff`。
- 出图：`npm run export`，可加参数指定倍率，例如 `npm run export -- 1`。
- 校验：`npm run check`，即 TypeScript 类型检查。

## 1. 画风基准

目标画风是 HD-2D 式小人：分辨率低，但色阶丰富、明暗对比强、颗粒感粗。细致感靠色阶和明暗，而不是靠堆像素。

| 项 | 标准 |
| --- | --- |
| 帧尺寸 | 42 × 62 像素（单位画布 64 × 96 × 倍率 0.65），角色身高约 36 像素 |
| 比例 | Q 版约 2.1 头身：头大，身体短，手脚小 |
| 色阶 | 每个部件 5 个手写色，相邻两色之间在 OKLab 里自动插 3 个过渡色，共 17 阶；色阶交界用 4 × 4 Bayer 有序抖动打散 |
| 最暗阶 | 直接用描边色：深阴影和轮廓融成一片，形体更有分量 |
| 描边 | 自动 1px。外轮廓：受光侧（左、上）用浅描边，背光侧（右、下）用深描边。部件之间的内描边（压在别的部件上的那一段）改用本部件自己的暗色（0.75 阶），不再是近黑的线 |
| 光源 | 统一在左上偏前，即 `Brush.ts` 中的 `LX, LY, LZ` |
| 粗粝感 | 量化前叠加斑块噪声（`g.grit`）。布料 0.16–0.26；皮肤 0.07–0.08，保持干净 |
| 体积光影 | 自上而下的整体渐变（`g.vgrad` = 0.24）；上层部件往右下投约 2 像素的接触阴影；暗面贴着轮廓的一圈有反光 |
| 采样 | 只做整数倍最近邻放大，不做模糊 |

倍率 `SPRITE_SCALE` 只影响输出密度。所有形状都用单位坐标描述，改倍率不需要改任何装备数据。0.65 是目前的定稿值；0.8 以上会变得细腻，但会失去粗粝感。

## 2. 坐标与骨架

所有形状都写在 **单位坐标** 中：64 × 96 的画布，原点在左上，y 向下。实际像素 = 单位 × `SPRITE_SCALE`。

| 常量 | 值（单位） | 含义 |
| --- | --- | --- |
| `CX` | 32 | 身体中轴 / 镜像轴 |
| `FOOT_Y` | 90 | 脚底所在行，也是导出的锚点 |
| `HIP` / `HAND` / `SHOULDER` / `NECK` / `HEAD` | 16 / 17 / 29 / 30 / 41.8 | 从脚底往上的高度 |
| `HEAD_RX` / `HEAD_RY` | 11.6 / 10.9 | 头的半径 |
| `torsoHalf` | 6.5 − 1.9·\|sin\| | 躯干半宽，侧面时变窄 |

`rig.ts` 中的 `makePose(dir, frame)` 给出每一帧的姿态：头、颈、肩、肘、手、髋、脚的位置，`bob`（呼吸或步伐下沉），以及双手锚点 `hand_R / hand_L`（坐标、角度、在身前还是身后）。

骨架内部是一套局部 3D 坐标（`side` 左右、`up` 上下、`fwd` 前后），按朝向旋转后投影到画面。部件只需写一次，5 个方向自动一致。装备数据只引用 `pose` 的关节，**不写死某个方向的像素坐标**。

## 3. 方向、帧与镜像

- 原生 sheet 有 5 行，依次是 S（正面）、SE、E（右侧）、NE、N（背面）。
- 每行 8 列：0–1 为待机（呼吸起伏 1 单位），2–7 为行走六帧。行走相位为 `(t + 0.5) / 6`，步幅最大时身体下沉 1 单位。
- NW、W、SW 由 NE、E、SE 整帧水平翻转得到，翻转轴为帧宽 / 2，与 `CX` 的偏差在 0.1 像素以内。
- 镜像后武器会换到另一只手，这是约定的取舍。
- 帧率：待机 1.6 fps，行走 10 fps，见 `Animator`。

## 4. 图层（从后到前）

| 图层 | 用途 |
| --- | --- |
| `cape` | 披风；背面时挎包也在这里 |
| `weapon_back` | 被身体挡住的武器 |
| `arm_back` | 远侧手臂和袖子 |
| `legs` | 身体：腿 |
| `bottom` | 下装 |
| `shoes` | 鞋 |
| `torso` | 身体：躯干 |
| `top` | 上衣 |
| `bag` | 挎包 |
| `arm_front` | 近侧手臂和袖子 |
| `mantle` | 肩披 |
| `weapon_mid` | 竖握长柄武器（S / SE / NE / N）：在手前，但被头挡住 |
| `hair_back` | 头后面那一侧的发束 |
| `head` | 头和五官 |
| `scarf` | 围巾颈圈 |
| `hair` | 头发 |
| `weapon_front` | 身前的武器；正侧面时竖握武器也在这层 |

- 默认 z 值为 序号 × 10。装备可以用 `layerOverride(dir, frame)` 把自己的某个图层插到别的位置。示例：红斗篷背面时 `cape → Z.mantle - 1`，盖住身体，但仍在头后。
- 同一图层内的先后顺序：身体 → 下装 → 鞋 → 上衣 → 挎包 → 围巾 → 头发 → 副手 → 主手。

## 5. 调色板

每个调色板写 5 个十六进制色，从暗到亮依次为：

| 下标 | 名称 | 用法 |
| --- | --- | --- |
| 0 | 描边 / 最深阴影 | 主色的暗色，**不用纯黑**；色相略偏冷 |
| 1 | 暗部 | |
| 2 | 主色 | |
| 3 | 亮部 | 色相略偏暖 |
| 4 | 高光 | |

- 自动派生：相邻两色之间在 OKLab（感知均匀的色彩空间）里插 3 个过渡色，共 17 阶（0、0.25 … 4）。暗部偏冷、亮部偏暖的色相差会被平滑带过去，不会发灰。另外派生受光侧的浅描边（描边色 55% + 暗部色 45%）。
- 绘制时写的是明暗阶，不写颜色：`g.t(lam, bias)` 把光照算成 0–4 的连续值，再按 Bayer 阈值落到相邻两档之一（`g.dither = false` 可关闭抖动）；`tone()` 是不抖动的版本。`DARKEN / LIGHTEN` 在已有像素上调亮或调暗一阶。
- 合成时自动加两种过渡，不用在装备里写：上层部件对下层的接触阴影（`PixelLayer.castShadow`），和暗面轮廓处的反光（`PixelLayer.bounce`）。
- 内描边改色也在合成时自动完成（`PixelLayer.drawOnto` 的 `innerLine`，值为 `paperdoll.ts` 的 `INNER_LINE`）。小尺寸精灵里描边原本占画面约 30%，改色后降到约 14%，色阶过渡才有空间显出来。装备里不需要、也不应该手动画内部的黑线。
- 只给一个主色时，用 `ramp(id, '#rrggbb')` 自动生成暗部偏冷、亮部偏暖的五阶。手写的 `pal(id, c0..c4)` 用于需要精确控制的部件，如皮肤、头发、金属。
- 调色板的 `id` 全局唯一，sheet 缓存以它为键。

## 6. 替换标准

### 6.1 通用规则（所有装备）

三类部件的新增方式不同：

| 部件 | 新增方式 | 两端共用 |
| --- | --- | --- |
| 发型、五官 | `Sources/Resources/CharacterParts/hair|face/` 下加一个 JSON | 是，同一份文件 |
| 衣服、鞋、围巾、挎包、武器 | `src/items/<分类>/` 下加一个导出 `ItemDef` 的 TS 文件 | 否，Swift 端要加对应的实现（见第 8 节） |
| 肤色 | `body.ts` 的 `SKIN_TONES` | Swift 端同名常量 |

注册表自动收集这两个目录，**不需要改核心代码，也不需要改导出脚本**。用代码画的装备格式如下：

```ts
export const myItem: ItemDef = {
  id: 'top_xxx',              // 全局唯一，前缀 = 槽位
  name: '中文名',
  slot: 'top',                // face / hair / top / bottom / shoes / scarf / bag / weapon_main / weapon_off
  palettes: { main: ..., trim: ... },
  variants: [{ id: 'red', name: '红', palettes: { main: ... } }], // 可选的换色方案
  parts: [{ layer: 'top', draw: (c) => { ... } }],
  layerOverride: (dir, frame) => ({ ... }), // 可选
  hides: ['bag'],             // 可选：穿上后隐藏的槽位
  hold: 'up',                 // 仅武器：'up' 竖握 / 'down' 剑尖朝下
};
```

1. **只用骨架关节定位。** 位置来自 `c.pose`，包括 `neckY / neckUp / torsoHalf / armR / armL / legs / head / proj()`，不写死某个方向的坐标。
2. **用 Brush 画，不逐像素点。** 可用的工具有 `ellipse / capsule / ribbon / fill / axis / tri / rect`。明暗交给 `g.t(lam)`，由光照决定，不手填。
3. **细节只画在本层已有的像素上。** 衣褶、纽扣、五官、缝线都要用 `g.clip = true`，或者 `g.fold()`（它内部已经 clip）。画到轮廓外的像素会被自动描边包一圈，在侧面形成凸起，这是之前「香肠」和「鼓包」问题的根源。
4. **侧面不能比身体宽太多。** 围在身上的东西（围巾、腰带、肩披）宽度要随朝向收窄，参考围巾的 `torsoHalf + 2.2 − 1.5·|sin|`；否则侧面会前后各凸出一截。
5. **小图案用像素矩阵。** 像搭扣这类需要逐格控制的细节，用 `frames: { S: ['43', '31'], ... }` 加 `anchor` 和 `offset`。一个字符 = 一格（`'.'` 为空，`'0'`–`'4'` 为明暗阶），一格的像素数随倍率取整。
6. **5 个方向都要有。** `frames` 写法里缺失的方向就不画，比如挎包的搭扣背面看不到。
7. **细节至少 1.5 像素宽。** 当前密度下 1 像素 ≈ 1.5 单位，比这更窄的镶边、金线会碎成一格一格的点。镶边带宽至少 2.3 单位；只在高密度下才有意义的细节用 `if (g.S >= 0.8)` 包起来。

### 6.2 五官（`face` 槽位，`Sources/Resources/CharacterParts/face/*.json`）

五官是纯数据：一套五官 = 一个 JSON 文件，放在 `Sources/Resources/CharacterParts/face/`。网页工具和 iPad 端读同一份文件。脸型（圆脸的轮廓、鼻子阴影、耳朵）属于身体，在 `src/items/body.ts`；眼、眉、嘴、腮红属于五官。

```json
{
  "id": "face_round",
  "name": "圆眼",
  "palettes": { "eye": [5 色], "blush": [5 色] },
  "variants": [{ "id": "amber", "name": "琥珀瞳", "palettes": { "eye": [5 色] } }],
  "patterns": {
    "front": ["000", "041", "012", ".23"],
    "side":  ["00", "41", "12", "23"],
    "far":   ["00", "01", "12", ".2"]
  },
  "views": {
    "S":  { "eyes": [["front", -5, 0], ["front!", 3, 0]], "blush": [[-6, 4], ...], "mouth": [[0, 5]], "brows": [[-5, -2], ...] },
    "SE": { ... },
    "E":  { ... }
  }
}
```

- **坐标**：原点是头中心的像素 `px = round(hx·S), py = round((hy + 0.4)·S)`（`hx = head.x + sin·0.9`）。单位是「格」，一格 = `max(1, round(S))` 个像素。倍率变了，五官大小和对称性都不变。
- **眼睛图案**：`patterns` 里自定义，每个字符一格：`.` 空，`0` 眼线，`1` 瞳孔，`2` 虹膜，`3` 虹膜亮部，`4` 高光。`views` 里引用图案名，名字后加 `!` 表示水平镜像。
- **颜色**：眼睛用 `eye` 调色板；腮红用 `blush` 第 2 阶；嘴和眉用身体的 `skin` 第 1 阶，换肤色时一起变。
- **方向**：只写有脸的方向，一般是 S、SE、E。NE、N 看不到脸，不写。W、NW、SW 由镜像得到。
- **正面左右对称。** 对称轴在 `px + 0.5`：x 在 −5…−3 的元素，镜像位置是 3…5；单像素的嘴放在 0 列正好居中。
- **只画在脸上。** 五官部件用 `mask: 'below'`：只写到已经画好的脸部像素上，不描边，所以永远不会在轮廓外鼓出小包。不需要也不能靠调位置把元素放到脸外面。
- **眼睛要有神。** 正面眼建议 3 × 4：第一行整行眼线，高光放在第二行中间那格。`face_smile.json` 是另一种画法：闭眼笑，眼睛是一道弧线。
- **参考位置**（`face_round.json`）：

  | 方向 | 眼 | 腮红 | 嘴 | 眉 |
  | --- | --- | --- | --- | --- |
  | S | −5 / +3（镜像） | 两侧第 4 行 | 0 列，第 5 行 | 第 −2 / −1 行，外高内低 |
  | SE | 近眼 −2，远眼 +5 | 左侧 | 3–4 列 | 近眼上方 |
  | E | +4 | +2 / +3 | +6 列 | +4 / +5 |

- **脸型（`body.ts`）**：上半张脸是椭圆；下半张脸几乎不收窄（只收 5%），高度只有上半的 0.84，形状接近正圆，下巴两角是圆弧。下巴必须收在围巾颈圈上缘之上，中间露出一道脖子阴影，否则下巴会被围巾切成一条平线，看起来像方脸。脸的光照压缩在 暗部…亮部 之间（`lam × 0.62 + 0.2`），grit 取 0.07；额头 `dy < −3.4` 一律压成暗部，表示刘海的阴影。侧面不画突出的鼻尖，只在脸的前缘打一点暗部。
- **肤色**：`SKIN_TONES`（fair / light / tan / deep）在 `body.ts`，用 `Equipment.setBodyPalette(...)` 或角色预设的 `skin` 字段切换。

### 6.3 发型（`hair` 槽位，`Sources/Resources/CharacterParts/hair/*.json`）

**总原则：这个像素密度下，发型越简单越好看。** 头只有约 15 像素宽，一缕一缕深浅不同的细碎层次只会变成噪点。发型应该读成一整块：大块亮面加大块暗面，一道高光带，两三条发束缝交代走向，刘海下缘有参差的发梢。不要为了「细节」叠加更多发束。

头发由少量贴在椭球上的宽发束组成。每个方向都由同一组发束投影得到，所以正面、侧面、背面自然一致。

**头发椭球**：左右半径 `RX ≈ 12.9`，上下 `RY ≈ 12.3`，前后 `RZ ≈ 11.4`（基准 11.6 / 11 / 10.2 乘以 `HS`，`HS` = 头的半径 / 10.4，头放大时发型和发束宽度一起放大）。前后半径必须比左右小，否则侧面头会被拉成横向的长条。俯视角为 18°。

发型也是纯数据：一个发型 = 一个 JSON 文件。引擎在 `src/items/kits/hairKit.ts`（Swift 端是同一套算法）。

```json
{
  "id": "hair_messy",
  "name": "蓬松短发",
  "palette": [5 色],
  "variants": [{ "id": "black", "name": "墨黑", "palette": [5 色] }, { "id": "red", "name": "赤红", "base": "#b03a26" }],
  "hairline": [[0, 50], [70, 50], [100, 95], [100, 118.02], [180, 129]],
  "locks": [{ "phi": -47.26, "a1": 63.06, "twist": 16, "width": 3.3 }, ...]
}
```

- `variants` 可以手写 5 色（`palette`），也可以只给一个主色（`base`），自动生成暗部偏冷、亮部偏暖的五阶。
- `hairline` 是发际线：`[方位绝对值, 纬度]` 的折线，按方位分段线性插值；同一方位写两次表示在这里跳变（耳朵前后）。
- `locks` 里没写的字段取默认值：`a0` 5，`twist` 0，`flick` 1.06，`lift` 0，`tier` 0。发束的先后顺序会影响走路时各缕甩动的相位，改顺序会让动画略有变化。
- 现有两个发型：`hair_messy.json`（蓬松短发）和 `hair_neat.json`（利落短发，斜分刘海、后发更短），可以对照着改。

**发束数量（上限）**：

| 部位 | 数量 | 宽度 `width` |
| --- | --- | --- |
| 刘海 | 4 | 3.3 |
| 鬓角 | 左右各 1 | 3.4 |
| 后发 | 4 | 3.8 |
| 头顶短翘发（`tier: 1`） | 3，只为打破圆形轮廓 | 2.6 |
| 呆毛（`tier: 2`） | 1 | 0.9 |

每一缕 `Lock`：

| 字段 | 含义 | 建议范围 |
| --- | --- | --- |
| `phi` | 方位角：0 = 脸正前方，+ = 角色左侧，±180 = 后脑 | |
| `a0 / a1` | 起止纬度，0 = 头顶 | 刘海 a1 62–74；鬓角 90–100；后发 120–135；短翘发约 40 |
| `twist` | 发梢在方位上拧的角度。刘海整体同向拧，形成斜刘海 | 刘海 16，其余 ±8 |
| `flick` | 发梢外翘比例 | 刘海、鬓角、后发 1.06–1.08；短翘发 1.18 |
| `lift` | 发根离头皮的高度 | 短翘发 0.04，其余 0 |
| `width` | 最大半宽（单位，绘制时再乘 `HS`） | 见上表 |
| `tier` | 0 发束 / 1 头顶短翘发 / 2 呆毛 | |
| `tint` | 单缕偏亮或偏暗 | **固定为 0**，不做一缕一缕的深浅差 |

**明暗**：

- 以整颗头的受光为主（左上亮、右下暗，系数 0.95），发束自身的圆柱光照只占 0.3。
- 发根底色也按整体受光着色，只是偏暗，发束之间的缝隙不会是黑点。
- 发束之间的缝只比周围暗 1.5 阶，而且只在发束后段出现，不用深描边。
- 天使环是画面上一道向两侧下弯的弧形光带（头中心往上 0.30–0.46 个半径），只出现在受光的左上那一侧，最亮处用高光色。
- 头发的颗粒噪声 `grit` 为 0.1，是布料的一半左右。

硬性要求：

1. **鬓角放在方位 ±92°–110°**（耳朵前后），只垂到脸颊上半（a1 ≤ 100）。方位小于 85° 时侧面会把脸颊整块盖住；垂得太长会把正面的脸夹成竖长方块，失去圆脸。
2. **刘海不压眼睛**，`a1 ≤ 74`。中间一缕可以略长，垂到两眼之间。
3. **不露头皮**：发束下面有一层按 `hairline(phi)` 计算的发根底色。改发际线时，前额 50°（方位 < 70°），耳前只盖到脸颊上半，过渡到 95°（方位 100°），后脑约 118°–129°。
4. **分两层**：`hair_back` 放在头后面那一侧（`near < −0.12`）的发束，`hair` 放其余发束和发根底色。
5. **发束随机数用固定种子**，每次烘焙结果一致。
6. **配色**：手写 5 色，色相从暗部的红棕过渡到亮部的金色。发色变体写在 `variants` 里。

新发型的做法：复制一个现有的 JSON，改 `id`、`name`、发束表和发际线，并遵守上面的数量上限。短发调小 `a1`，长发增大 `a1`。马尾这类发束表画不出的形状，需要在 `hairKit.ts` 里给引擎加新能力（两端都要加）。

### 6.4 衣服（`src/items/top|bottom|shoes|scarf|bag/`）

**上衣（top）**
- 躯干用 `torsoShape(c, rows, { flare }, shade)`。`rows` 取 12.8–14 单位（从颈部往下），要 **完全盖住** 皮肤躯干（12.5 单位），下摆张开 `flare` 为 1.2–2。下摆镶边至少 3 单位高，否则会被双手和挎包挡没。
- 袖子用 `sleeveParts({ key, cuffKey })`：自动处理近侧和远侧手臂的图层、肩头和肘弯，袖长为前臂的 0.72。
- 颈部 2.6 单位以内压成描边色，表示围巾或下巴的阴影；下摆镶边上方压一道暗线。
- 只有 `pose.cos > 0.3` 时才能看到正面细节，如门襟、翻领、扣子。背面画后中缝和腰带，侧面画侧缝和口袋。

**披风 / 斗篷**
- 画在 `cape` 层。正面和侧面能看到的是内衬（暗色），背面和侧面看到外侧。
- 背面用 `layerOverride` 把 `cape` 提到 `mantle` 之下，盖住身体。
- 褶皱用 `sin(nx · folds · π)`，越往下越深；下摆随褶皱起伏，走路时摆动。

**下装（bottom）**
- 两条裤腿各占一个部件，交叉时中间有描边分开。
- 裤脚画到 `foot.y − 5`，和靴口重叠。
- 胯部整体压暗约 −0.15，表示在上衣的阴影里。

**鞋（shoes）**
- 靴筒加翻边，从脚底往上约 7 单位。
- 鞋头按 `pose.sin × 2.1` 朝前伸；正面时多一行。
- 鞋底一律为描边色。远侧的那只鞋整体压暗。

**围巾（scarf）**
- 颈圈画在 `scarf` 层，中心在 `neckY + 2.1`，半高 2.6（上缘要低于下巴）。半宽为 `torsoHalf + 2.2 − 1.5·|sin|`，轮廓是圆头（指数 2.6 / 3），不是方筒。
- 正面加一个围巾结和垂下的一段，末端带两道浅色条纹。
- 飘在身后的尾巴不烘焙进 sheet，由 `tail` 定义挂点、节数和每节长度，运行时用弹簧链驱动（见第 8 节）。

**挎包（bag）**
- 包挂在右胯前。背面时包体放进 `cape` 层，只从身侧露出一点。

### 6.5 武器（`src/items/weapon/`）

- 按手部锚点画：`c.hand` 给出坐标和 `angle`，用 `g.axis(x, y, dx, dy, t0, t1, half, fn)` 沿武器方向绘制，`t` 为沿杆距离，`o` 为横向偏移。
- `hold: 'up'`（法杖类）：竖握在身侧，正侧面时杖头前倾、从脸前经过。图层自动选择：身后 → `weapon_back`；正侧面 → `weapon_front`；其余方向 → `weapon_mid`。杆长不超过手上方 40 单位，杖头不出画布。
- `hold: 'down'`（剑类）：手臂下垂，剑尖朝前下方。身前 → `weapon_front`，身后 → `weapon_back`。
- 主手为 `weapon_main`（右手），副手为 `weapon_off`（左手），副手槽也可以装主手武器。

### 6.6 角色预设（`src/items/characters.ts`）

一个角色 = 套装 + 发型 + 五官 + 肤色 + 武器 + 各槽位的换色方案：

```ts
{ id: 'hero3', name: '林间行者',
  outfit: 'traveler', hair: 'hair_messy', face: 'face_round', skin: 'tan',
  variants: { top: 'green', scarf: 'cream', hair: 'blonde', face: 'amber' } }
```

预览页和导出脚本都按这份清单出图。`hero1`–`hero3` 对应游戏里的三位旅人，导出为 `Hero1Directions.png` …，与 `Assets.xcassets` 中的资源同名。找不到的装备 id 会直接报错，不会悄悄画出缺件的角色。

## 8. iPad 游戏：实时换装

人物不再依赖预先画好的图片：游戏启动时，Swift 版烘焙器按角色预设现场合成三位旅人的图集，运行时也可以随时换装。

### 8.1 组成

| 位置 | 内容 |
| --- | --- |
| `Sources/Game/Characters/` | Swift 版烘焙器：调色板（OKLab 17 阶）、像素图层、画笔、骨架、纸娃娃合成、衣服与武器、发型引擎、五官引擎、装备目录与角色预设、图集烘焙 |
| `Sources/Resources/CharacterParts/` | 发型、五官 JSON，以文件夹引用整体打包进 App；网页工具读同一份 |
| `Sources/Resources/Assets.xcassets/HeroNDirections` | 网页工具导出的同格式图集，只在现场烘焙失败时作为回退 |
| `Tests/CharacterSpriteTests.swift` | 数据解码、预设完整性、图集格式、换装生效，以及与网页端出图的一致性测试 |

两端文件一一对应：`SpritePalette` ↔ `palette.ts`，`PixelLayer` ↔ `PixelLayer.ts`，`SpriteBrush` ↔ `Brush.ts`，`CharacterRig` ↔ `rig.ts`，`Paperdoll` ↔ `paperdoll.ts`，`ItemHelpers` ↔ `shared.ts`，`BodyItem` ↔ `body.ts`，`ClothingItems` / `WeaponItems` ↔ `items/*`，`HairKit` / `FaceKit` ↔ `kits/*`，`CharacterCatalog` ↔ `registry.ts` + `outfits.ts` + `characters.ts`，`SpriteBaker` ↔ `scripts/export.ts`。

### 8.2 换装接口

```swift
var look = CharacterCatalog.characters[0]          // 从预设出发
look.hair = "hair_neat"                           // 发型（CharacterParts/hair 里的 id）
look.face = "face_smile"                          // 五官（CharacterParts/face 里的 id）
look.skin = "tan"                                 // 肤色：fair / light / tan / deep
look.weapon = "weapon_staff"                      // 武器，nil = 空手
look.variants[.top] = "green"                     // 各槽位的换色方案
gameScene.setAppearance(look, forTraveler: 0)     // 立即重新烘焙生效
```

`setAppearance` 遇到找不到的装备 id 会返回 `false`，外观保持不变。底层接口是 `CharacterCatalog.equipment(for:)` → `Equipment`（`equip / unequip / setVariant / setPalette / setBodyPalette`）→ `SpriteBaker.atlas(_:)`。

- **纹理**：一律用 `.nearest` 采样，像素画缩放时不发糊。
- **性能**：一次换装只烘焙图集用到的 12 帧（3 个方向 × 4 帧），不是全部 40 帧。
- **尺寸**：图集格式与原来相同（1536 × 1536，4 × 4，脚底在 y = 336，`anchorPoint = (0.5, 0.125)`）。显示尺寸 64 × 64 时人物约 30 pt 高。

### 8.3 两端保持一致

| 改什么 | 网页工具 | Swift |
| --- | --- | --- |
| 发型、五官 | 改 / 加 `CharacterParts` 里的 JSON | 自动生效，同一份文件 |
| 衣服、武器 | `src/items/<分类>/*.ts` | `ClothingItems` / `WeaponItems` 里加对应实现，并在 `CharacterCatalog` 登记 |
| 角色预设 | `src/items/characters.ts` | `CharacterCatalog.characters` |
| 引擎算法（光照、描边、抖动等） | `src/pixel`、`src/character` | 对应文件同步修改 |

移植时最容易出错的地方：JS 的 `Math.round` 对负的 .5 往大取整（Swift 版用 `jsRound`）；哈希噪声依赖 32 位整数溢出（`&*`、`&+`）；接触阴影的缓冲是 32 位浮点；排序要稳定（深度相同时保持原顺序）。

**一致性测试**：`testBakedAtlasesMatchWebExport` 把游戏现场烘焙的图集与资源里网页端导出的 `HeroNDirections` 逐像素比对，不一致的像素须少于 2%（容许两端数学库在最后一位上的差异）。所以：

1. 改了网页端的任何东西，执行 `npm run export`，再把 `export/ios/Hero*Directions.png` 拷进对应的 imageset。
2. 再同步修改 Swift 端，跑单元测试。测试失败说明两端走偏了。

### 8.4 导出文件

`npm run export` 对每个角色预设（见 6.6）输出以下文件，另附一份 `manifest.json` 列出各角色的装备和换色，都已提交在 `hd2d-walk-demo/export/`：

| 文件 | 内容 |
| --- | --- |
| `ios/Hero<N>Directions.png` | 1536 × 1536，4 × 4，每格 384 × 384，与游戏格式一致。行：正面、左、背面、右。列：待机、左脚在前、过渡、右脚在前，对应原生第 0 / 6 / 5 / 3 列。5 倍最近邻放大，脚底在 y = 336 |
| `native/<name>.png` | 原生 sheet：5 行 × 8 列，每格 42 × 62（Swift 端：`SpriteBaker.sheet(_:)`） |
| `native/<name>.json` | 帧尺寸、脚底锚点、镜像规则、帧率、装备与调色板、每帧双手锚点与 `bob`、围巾尾挂点与参数 |

**升级到 8 方向 / 6 帧行走**（可选）：

1. 用原生 sheet，按 JSON 中的 `frameSize` 切帧。`anchorPoint = (pivot.x / w, 1 − pivot.y / h)`。
2. W、NW、SW 用 E、NE、SE 的帧，并设 `xScale = -1`。
3. 行走动画按 `fps.walk`（10 fps）循环第 2–7 列，待机按 `fps.idle`（1.6 fps）循环第 0–1 列。

**围巾尾（游戏端尚未接入）**：

- 数据：JSON 的 `frames[行][列].scarfTail` 是每帧的挂点（像素坐标，`front` 表示画在身前还是身后）。顶层的 `scarfTail` 给出节数、每节长度和调色板。
- 算法（`src/character/scarfPhysics.ts`）是一条 Verlet 质点链：
  - 根部钉在挂点上。
  - 受力 = 反向移动速度 × 9 + 偏向一侧的静止力 + 两组正弦微风，加重力 200。
  - 速度阻尼为每秒保留 2%，约束迭代 4 次。
  - 画成一条带子：根部粗，末端细，靠近末端有两道浅色条纹，外加 1px 描边。
- 在 Swift 里每帧更新质点，用 `SKShapeNode`，或者先画到一张小纹理上再按最近邻显示，放在人物节点前面或后面。
