# 验收分两段：母版交接、模组输出

> 当前实际进度（2026-11-07）：两件均由用户选定B，且授权一次完成全部方向；八向分层母版和原行走模组输出已制作，见根 ART_TASKS.md 与 Art/Review/P1/chat-apparel-v2-b-eight-way-r1/README.md。新资源/动作认可待反馈，未接入App。下文为通用制作/交接规范，不把空模板当实际进度。

## A. Chat交回母版时

| 检查 | 明确通过条件 | 退回情况 |
| --- | --- | --- |
| 数量 | 单件5view×4层＝20项，必要右向补图另列 | 只有整人概念图却称母版完整；缺一侧袖子 |
| PNG | 256×256、RGBA、真透明、同view同坐标；alpha0处RGB0 | 白底/棋盘格截图、裁切居中、尺寸不同、拉伸人物 |
| 内容归属 | 四层只有各自衣物，肩甲在袖层，腰带在torso | 夹带手/底衣；胸甲重复肩甲；裙甲混裤腿 |
| 服帖 | 原人物同尺寸合成，肩腋腕腰连续，胸腹贴合 | 鼓肚、胸口凸块、袖腕错位、腰带杂色、裙甲切裤 |
| 五视角一致 | 同件衣服，衣长/结构/甲片/装饰一致 | 正面压窄作侧面、转背出现胸徽、光照翻错 |
| 主题 | 1×可读胸/肩/腰裙结构和材质 | 只换色/胸徽，或依赖光晕掩盖形体 |
| 清单/源稿 | 20层路径、palette、提示词/原稿、真正可编辑语义层 | 虚构路径、空PSD、整人嵌入SVG冒充分层 |
| 状态 | 明确C阶段、实际检查/缺项；用户认可为null | 把选A方案说成全部动画或游戏完成 |

保留合法露颈与隐藏接合；未设计的游离像素、残边与错误皮肤内容要清理。不靠肤色阈值/最大连通域粗删来自动通过。只能交概念或部分母版就如实标注，不伪造alpha、源稿、SHA或未执行检查。

**此处不要求Chat交104动作图、416动作层、运行asset.json或行走GIF。** 母版通过也不代表动画适配完成。

## B. Codex复用模组后

| 检查 | Codex要做什么 | 失败时优先修哪里 |
| --- | --- | --- |
| 身体保护 | 原身体/头脸/手/裤靴/武器/关节/motion/drawOrder不变 | 新母版、裁片、注册，不改人体迁就衣服 |
| 肩与衣身 | 护肩随对应臂，胸甲不被双肩差摆扭成扭肩 | 肩甲归属、共用袖甲/衣身控制参数 |
| 关节接缝 | 逐侧肩肘腕、正左/正右腕口、背斜近远遮挡 | 母版接合/方向映射；少数特例记录可重导局部修正 |
| 腰裙髋腿 | 裙片随原髋腿，不夹裤腿、不出现臀腿洞 | 衣片分区/表面映射，不重画裤子 |
| 右向派生 | 自身左右、近远、光照与不对称装饰正确 | 必要右向母版/投影修正，不直接翻图即通过 |
| 完整导出 | 8×13＝104唯一绑定，每条四槽，共416引用 | 修导出缺项，不向Chat派104次手绘 |
| 动图 | 各向walk8×120ms；原入口/出口的正常起停 | 真实接缝/步相，不复制帧或拉慢掩盖 |
| 组合 | 单件2发型×2五官×背剑开关＝8组，104姿势实际合成 | 新衣遮挡/接合；不改旧部件打补丁 |

每件832次、两件1664次合成是**程序产物的审核量**，不是Chat画图数。新甲与旧蓝衣/绿衣/另一甲互斥，不靠叠穿遮漏。

主线程亲看全身1×/2×、正常速度实际帧、08→01、起停、跳亮、边缘和背剑，先修明显问题再交用户。自动数量/alpha/连通检查不能代替肢链与服帖观察；只能看GIF解码静帧时如实记录，不能称连续播放或实机验收。

## 权责与认可

- Chat：设计、母版和真正做过的文件自查；不越过C段称游戏已接入。
- Codex：登记母版、复用动作/挂载批量导出、修复与主线程审核，再交正常GIF。
- 用户：选择设计、认可实际展示范围，之后做实机体验；选概念不等于认可母版/104姿势/战斗/安装包。

本任务不新增战斗动作、人体、运行时代码或IPA。模板保持格式示例的未填写/null，实际新甲进度读根 ART_TASKS.md 和新资源清单。母版文件可用`scripts/check-apparel-master.py`核规格；它不自动评分美术，也不替代后续适配。

参考包解压后可执行：`python tools/check-apparel-master.py examples/blue-coat-masters/master-manifest.json`。检查新包时换成其清单路径；C2只有front时可显式使用`--partial`，输出会标非完整五视角，不可冒充完整母版。没有执行能力时只写未验证。
