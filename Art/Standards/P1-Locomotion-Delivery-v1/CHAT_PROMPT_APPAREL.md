# 给 Chat 对话使用的服装制作任务书

把本文件复制到负责绘图的 Chat 对话，并一并提供文末列出的项目参考。服装设计、部件绘制、正式装配和最终验收分开处理：Chat 交艺术资源与源稿，我再负责接入、完整组合检查和修复。不要把概念预览说成完整游戏资源。

## 可直接复制给 Chat 的任务

```text
你负责为像素风游戏 Meadow Journey 的 P1 主角制作可挂载的上衣/盔甲美术资源。服装目标/名称：【填写，例如星辉甲、龙纹甲】；设计要求/参考：【填写】。不要复用此前被用户认为过于朴素的候选，也不要只给旧稿换颜色。

我会附上项目的角色和服装参考图、现行制作标准及需要的姿势参考。请严格沿用参考人物的身体比例、头身比、像素密度、描边、固定左上光源和已有步态。参考图中的人物只用于比例、位置、材质风格和遮挡关系；正式服装资源必须是独立透明服装部件，不重画或夹带人物。

先做设计选择阶段：每件服装提供3个结构明显不同的设计方向。不能只换颜色或胸前徽章；应在甲片/衣身版型、肩部结构、领口、腰部和下摆层次上做出可读差异。整体要比普通制服更有主题感和材质层次，但细节控制在游戏原有像素尺寸能看清的范围，避免堆满小装饰、软糊光效、照片质感和AI随机纹样。三款都合成到同一张项目角色参考上，人物尺寸、姿势和位置完全相同，并附正常速度预览。等我选定后，只扩展所选设计，不要先把多个未选方案全部画成全套动作。

选定后先交一个可审核样包：正下 idle00 和正下 walk01–08。随后才制作完整资源。项目完整服装包必须覆盖8个方向（down、down-left、left、up-left、up、up-right、right、down-right）×13个姿势（idle00、walk01–08、walk-start01–02、walk-stop01–02），共104条显式绑定。步行、起步、收步按每帧120ms制作。若无法交齐，明确写成“阶段样稿/部分覆盖”，不可把缺帧、静止衣服贴图或自动镜像称为完整八向资源。

每个姿势按服装语义分开输出，单件PNG只画自己负责的衣物槽：
- outfit.torso：衣身/胸甲；
- outfit.sleeve.left 和 outfit.sleeve.right：左右袖/臂甲，左右按角色自身解剖方向命名；
- outfit.hem.front：前衣摆/护裙；没有该部件时仍提供透明占位图并在清单说明。

每个部件是固定256×256、左上为原点的透明RGBA PNG，sRGB、straight alpha，保留画布位置与透明边距；透明像素RGB归零。不要裁切后重新居中，不要按每帧内容自动缩放或拉伸，不要加入背景、人物皮肤、手、头发、脸、裤靴、武器、地面投影、文字、水印、格线或占位标签。可复用完全相同的PNG，但104个方向/动作/帧都必须在清单里显式登记。

服装必须贴合项目原人体和动作：肩—肘—腕、腋下、袖口、腰线、臀腿交界、裤口/靴口都不能出现洞、断层、漂浮轮廓或错误覆盖。袖子跟对应手臂动作，衣身跟躯干，衣摆随髋腿变化；禁止腿在动而裤/护裙不动、袖子脱离肩臂、手腕露出不该露的内层、白色内衣边漏出、两块衣片互相穿插、胸口凸起或衣服鼓成大肚子。接缝处需有稳定的隐藏重叠，不能靠裸肤洞、底衣补丁或另一件服装才能遮住。

保持原角色身体、肤色、头发、五官、骨骼关节、动作相位、帧序、画布和逐帧drawOrder不变；不制作角色本体，不改步态，不移动挂点，不添加外观专属代码。服装内的材质明暗可以画，但不能画地面阴影。左右方向不可直接整图镜像后不检查；近远侧、装饰方向、光照和衣襟必须符合各自视角。每个方向的长度和结构要一致，不能转向就变成另一件衣服。

交付内容：
1. 设计阶段：每款独立造型图、同一人物的合成对比图、名称/材质/结构差异说明。
2. 样包阶段：透明分层PNG、同一角色全身idle PNG、正下8帧×120ms正常速度GIF；所有帧位置对齐。
3. 完整阶段：8方向×13姿势的所有服装层PNG、104条绑定清单/manifest、可编辑源稿（ORA/分层SVG/PSD等）、原始参考与生成提示词、导出步骤、SHA256清单、全身合成图和正常速度GIF。保留透明通道；不要只给整人精灵表或一张合成角色图。

审核前自查：用项目原人物与drawOrder实际合成全部帧；以1×和2×查看完整人物比例，不只放大胸章；逐帧检查肩腕、左右手、臀腿、衣摆、裤靴、边缘杂色、接缝、遮挡和跳亮；解码检查GIF确实是8帧、每帧120ms。发现问题先自行修好再交。请在交付记录中准确区分“已生成”“已合成检查”“仍未验证”，不要宣称用户认可、完整接入、实机通过或IPA完成。

正式八向完成包按项目规范提供asset.json、authoring.json、独立部件PNG、可编辑源稿、新catalog和审核证据；所有路径必须真实存在。完整包还要有八方向各自的正常速度全身walk GIF和起停边界预览。只做设计样稿时，不要伪造这些生产文件。
```

此任务书默认针对上衣/盔甲的四个槽位。若具体任务改为裤子/靴子，使用 `outfit.pants.left`、`outfit.pants.right`、`outfit.boot.left`、`outfit.boot.right` 四个槽位，并按各自髋/膝/踝和足底动作检查；不要把上下装混在一张PNG里。

## 交给 Chat 时应附的项目参考

优先附上：

1. [已认可的正下全身站姿](../../Review/P1/modular-down-back-carry-v1/idle-review-2x.png)和[正常速度行走动图](../../Review/P1/modular-down-back-carry-v1/walk-120ms.gif)，让 Chat 按实际角色和材质语言设计。
2. 要求全八向时，附上当前基础人物各方向及动作参考，或提供仓库中的 `Art/Integration/P1-modular-eight-way-v1/motion.json`、`Art/Parts/P1-v1/eight-way-v1/base/` 与已认可衣服对应的独立服装层。只给全身截图不足以推导104帧的关节与遮挡。
3. 同时附上本目录的 `README.md`、`contract.json` 和 `Art/Standards/P1-Parts-v1/asset.schema.json`。Chat 无法读取仓库路径时，要把相应文件实际上传到对话。

本任务书是美术生成与文件交接标准，不能取代项目里的机器校验和人工审核。收到资源后仍需由主线程实际装配，检查所有帧、整身比例和正常速度动图；检查不通过的部分会先修复，不会直接进入游戏。
