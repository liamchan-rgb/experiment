# P1 向下换装模板小样 v1

以用户认可的向下 r1 为动作基准，验证头发、面部、上衣与武器能独立替换。当前为**向下单方向候选小样，外观尚待用户审核**。八方向的动作认可与本小样的美术认可分别记录。

## 打开和检查

**iPad 请直接打开[在线换装预览](https://p1-character-atelier.smokytide.chatgpt.site)**，无需下载或解压。本地 HTML 在 iPad“文件”预览中通常不能完整执行交互脚本。在线页面为私有访问，登录当前 ChatGPT 账号即可。

下载整包解压，双击 `preview.html`，用浏览器打开即可。图片与数据全部内嵌，不需要安装、服务端或网络。仓库在线查看 HTML 会显示源码，需要下载后打开。

- 左边始终播放已认可原动作，右边切换外观；16 种搭配均共用相同的站姿和八张步行关键姿势。
- 栗色碎发／银色短发，蓝眼平静／金眼微笑，蓝色旅装／绿色游侠，空手／短剑。
- 点击 00 看站姿；点击 01–08 暂停逐帧检查。正常 120 ms／帧，慢速 480 ms／帧，站姿不参与行走循环。
- “查看挂点”显示头部、左右手与鞋底标记；“查看分层”可检查遮挡。隐藏头发、面部或衣物时，显示补画的头部／躯干底稿。
- 可导出透明当前帧 PNG、完整动作图集 PNG、搭配 JSON。导出不包含对照底色、编号或挂点。分层开关会作用于导出的 PNG。

## 文件与编辑方式

| 位置 | 内容 |
| --- | --- |
| `reference/00.png`–`08.png` | 已认可原始注册单格的逐字节副本，作为动作参照 |
| `art-source/`、`generation.json` | 六份图像工具原稿、真实提示词、参照和 SHA-256；未覆盖原稿 |
| `source/frame-specs.json` | 可编辑的每帧挂点、相位、身体关节、脸部切分路径和部件尺寸 |
| `layers/00/`–`08/` | 全画布透明部件 PNG；不需要按外接框重新定位 |
| `editable/chestnut-blue-traveler-empty/` | 原搭配九帧 ORA 和 SVG；默认可见层可还原原动作 |
| `editable/silver-amber-ranger-sword/` | 银发游侠持剑搭配九帧 ORA 和 SVG |
| `appearances/` | 16 份预合成透明图集，各 2304 × 256，00 站姿后接 01–08 |
| `manifest.json` | 部件选项、层序、每帧挂点、脚底标记、时长与图集索引 |
| `validation.json` | 导出、动作保护和浏览器功能检查结果 |

ORA 可用 Krita 等支持 OpenRaster 的编辑器逐层编辑；SVG 每个命名组内嵌一张透明部件 PNG，是分组的位图源文件，不是矢量重绘。可编辑格式已做文件结构和图层重合成检查，尚未在桌面美术软件中做 GUI 往返保存测试。

原搭配的 ORA/SVG 额外保存默认隐藏的 `underpaint` 头部／躯干底稿。隐藏头发或衣物进行编辑时可打开底稿。原 PNG 人物内部 alpha 约为 253，直接在其后铺底会改变原像素；默认搭配因此保持不铺底，新头部搭配使用 `body-filled`。这个区别用于保留原动作，不改变配件挂点。

## 模板约定

画布固定 256 × 256；坐标原点在左上，x 向右、y 向下。**角色自身右手在画面左侧**。所有部件均在该完整画布内注册，替换头发或衣服时不按新轮廓缩放整个人物，不重新对齐鞋底，也不重新生成腿脚。

从后到前：身体 → 武器 → 衣物 → 面部 → 头发 → 前景手部。短剑以局部握柄点 `[9.5,14]` 挂到逐帧 `rightHand`，再按 `swordAngleDeg` 旋转；原手部位于武器前面，遮挡握柄。此层序只适用于本轮向下持剑，不能直接套到背面方向或攻击动作。

头发和新面部以头部挂点对齐；绿色游侠装包含衣物限定的绿色材质，以及单独绘制的胸前系带背心。沿用原短外套袖型、袖口和下摆；裤腿、靴子与摆动相位保持原样。现有九帧是绘制好的关键姿势，髋／膝／踝标记用于部件定位参考，**不是已经验证的骨骼绑定或物理足底数据**。鞋底标记从原靴子轮廓测量，只作检查参照。

身体底稿补了头皮和无饰内衫躯干；衣物下面的完整上臂／前臂及可适配任意衣型的裸模尚未建立。本轮可替换同袖型的上衣变体；长袖形变、长裙、大盔甲、长发背层、身体体型和肤色还需补画与适配。预览当前选择预制部件，不提供任意图片上传后自动绑定。

## 在仓库中重新导出

需要 Python 3、Pillow、NumPy；浏览器验证另需 Playwright 和 Chromium。

```sh
python scripts/build-character-template-pilot.py
python scripts/validate-character-template-pilot.py
```

脚本位于仓库根目录的 `scripts/`。修改原稿或 `source/frame-specs.json` 后重新导出；不编辑 `reference/` 来改动作。新增部件时先遵守全画布、挂点和遮挡约定，再扩展脚本的选项清单与 manifest。当前两份 ORA/SVG 搭配用于逐层美术编辑，其余组合由透明部件组成。

## 验证与后续范围

九帧默认搭配与已认可原图的可见 RGBA 一致；透明像素的无效 RGB 归零。144 种“搭配 × 姿势”均验证腿脚核心像素不变、画布不裁切，武器握柄与手部挂点落在有效图像内。18 份 ORA 可见层重合成与相应图集一致；六份 GIF 的八帧顺序范围、120／480 ms 和无限循环标记已核对。浏览器检查 16 份合成图集、选择器、逐帧、播放速度、分层及三种下载；桌面与 390 px 宽布局无横向溢出。

管理环境的 Chromium 策略阻止 `file://` 导航，验证时把**同一份完整 HTML**直接载入浏览器并阻断全部网络请求，离线内嵌资源与下载检查通过；未声称验证了该受管浏览器的文件导航。浏览器预乘 alpha 与 Pillow 存储的微小舍入差异记录在 validation.json。

八方向动作锁定清单在仓库 `Art/Templates/P1-Motion-v1.json`。其他七个方向尚未分层；当前小样审核后，才能按各方向补齐头部角度、衣物与武器遮挡。原应用仍加载旧图集格式，不能直接把九格小样替换进旧的 25 格加载器；后续需接入 manifest、预合成缓存和正确的动画索引。本轮未修改正式运行资源或 IPA，也未执行原生应用构建。

文件检查不代表用户认可新外观和动画观感。
