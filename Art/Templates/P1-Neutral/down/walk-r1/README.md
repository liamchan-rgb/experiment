## 同一个底模如何用于每一帧

每帧都是八个独立 256 × 256 透明部件：头、躯干、左右臂、左右手、左右腿脚，共 72 张 PNG。所有外观将共用这些底层，不按头发、眼睛或服装 ID 换人体。

- **头部与躯干直接复用已认可站姿图层**，只按动作数据做整数平移；九帧的头型、肤色、内衣与短裤一致。96 × 96 公共头板与每帧头层逐像素对应。
- **四肢动作由图像工具绘制**，按已认可向下相位逐张参照。源图统一使用 `1254 → 256` 的固定整画布变换：`x'=0.16*x+25, y'=0.16*y+38`；不按 alpha 外接框缩放、不单独把脚缩小或转向、不生成插值姿势。
- 源整人图只提供当帧四肢；导出时使用 `extraction.json` 明确的解剖边界，保留独立手掌及腕部重叠。短裤下的完整髋部连接复用共同底模；过腿时被另一腿挡住的小段支撑小腿另有明确隐藏补全区域。导出完成后，运行时只读独立 PNG，不运行猜色切图逻辑。
- `motion.json` 记录每帧头部变换、肩肘腕／髋膝踝、双手握持点、足底标记、朝向、支撑腿和身体层序。07 的摆动右腿在左支撑腿之前显示。握持角度暂用竖直候选值，尚未通过真实武器美术验收。

## 文件与复现

- `frames/00.png`–`08.png`：实际合成；00 与已认可站姿 PNG 字节一致。
- `layers/00/`–`08/`：各帧八层 PNG，保留完整共同画布。
- `editable/`：九份八层 ORA、九份分组位图 SVG，可编辑与重新导出。
- `shared/head-down.png`：共同头板；`shared/idle-approval.json`：站姿认可记录副本，其摘要相对路径以原站姿目录为准。
- `asset.json`：声明 `down / idle / 00` 和 `down / walk / 01–08` 的实际资源包。
- `source/`、`generation.json`：所选图像工具原图、真实提示词、引用及 SHA-256；`references/motion/` 保留原已认可相位参照。
- `drafts/`：未采用的初稿和中间修订，只保留制作历史，不参与合成。
- `extraction.json`：源稿部件归属、隐藏补全部位与导出边界，不是新外观需要复制的运行时代码。
- `validation.json`：实际部件、接缝、头部、ORA、循环、原素材保护与独立重导检查。

在仓库中重新导出：

## 验证范围与后续

72 张图层、九份 ORA 重合成与实际 PNG 一致；公共头部／躯干整数平移前后保持 RGBA 像素；63 组颈、肩、腕、髋接缝有至少两行强 alpha 重叠。各独立部件及合成人体构成一个强 alpha 连通分量，避免误带相邻部件的孤立细条；握持和关节标记位于对应部件。两份循环的帧序、量化像素、时长和循环标记通过。534 份此前 PNG／GIF 和全部 72 张已认可动作不变；144 份当时已有文件独立重导字节一致。

这些检查不代替步态、朝向和遮挡的美术审核。ORA 未在桌面绘画软件中做 GUI 往返保存，未做原生应用构建或实体 iPad 测试。正式运行资源、IPA 与历史在线换装演示未更新。

本目录保留已认可共同底模的向下行走；新增[独立头部资源与装配器候选](../../../P1-Modular/down/v1/README.md)另存另审。其他七方向中性人体、独立头发／五官／衣物／武器、通用装配器、交叉组合和第三件新资源零引擎／动作修改接入仍待制作。生产检查继续拒绝本包，不把向下一组导出成功记成完整换装系统完成。
